## PowerShell 中文编码坑

**背景：** 桌面上的 `彻底删除SQL_Server.ps1` 脚本在 PowerShell 中运行时出现中文乱码。

**问题根因：**
- Windows PowerShell 5.x 默认编码是 GBK（代码页 936），不是 UTF-8
- `.ps1` 文件若以 UTF-8 无 BOM 保存，PowerShell 5.x 会按系统默认编码（GBK）读取 → 中文乱码
- `Write-Host` 输出到控制台时，如果控制台代码页不是 65001（UTF-8），中文也会乱码

**解决方案（任选一）：**
1. **文件加 BOM：** 用编辑器将 `.ps1` 保存为 **UTF-8 with BOM**，PowerShell 5.x 能识别 BOM 并正确解码
2. **脚本开头加编码声明：**
   ```powershell
   [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
   $OutputEncoding = [System.Text.Encoding]::UTF8
   chcp 65001 | Out-Null
   ```
3. **改用 PowerShell 7+（pwsh）：** 默认 UTF-8，不会有这个问题
4. **控制台改代码页：** 运行前手动执行 `chcp 65001`

**最佳实践：** 写含中文的 PowerShell 脚本时，始终保存为 **UTF-8 with BOM**，这是兼容性最好的方案。
